---
name: contract
description: Turn an ODCS (Open Data Contract Standard) v3.0, v3.1, or v3.2 data contract into PQL.Assert DAX test suites for a PBIP semantic model, report which contract rules are enforced, run them, and trace failures back to contract rule ids. Requires `pip install pql-test[contracts]`.
version: 0.2.0
---

`pql-test contract` turns an ODCS data contract's quality rules into PQL.Assert `*.Tests.dax` suites. It reports every rule as mapped, approximated, or skipped, so no rule is silently dropped. It needs the optional MIT-licensed `pql-odcs` package: `pip install pql-test[contracts]`. The same commands, except `run`, are available standalone as `pql-odcs <command>`.

## Behavioral Contract

```sudolang
Interface Contract {
  generate CONTRACT MODEL_PATH --env ENV   // writes <Prefix>.<Suite>.<ENV>.Tests.dax into MODEL_PATH/DAXQueries/
  coverage CONTRACT [--format text|json]   // every rule: mapped | approximated | skipped (+ reason)
  lint CONTRACT [--model MODEL_PATH]       // ODCS schema validation + every name resolves
  trace CONTRACT RESULTS_JSON              // joins `pql-test run-tests --output` JSON to contract rule ids
  run CONTRACT MODEL_PATH --env ENV        // generate, then run the generated suites, then trace (pql-test only)

  exit_code: 0 | 1 | 2
    // 0 = success
    // 1 = contract invalid, lint problems, --fail-on-skipped triggered, or (run) a blocking suite failed / nothing ran
    // 2 = usage error: bad --env token, MODEL_PATH not a PBIP folder, or a file pql-odcs would overwrite without --force
}

Constraints {
  MODEL_PATH must be a PBIP folder (the root with the .pbip file, or the *.SemanticModel folder) in v0.1;
    local/<name> and <workspace>.Workspace/<model>.SemanticModel are NOT accepted yet
    (query-scoped XMLA runs arrive in v0.2, persistent deploys in v0.3)
  Suites are named <Prefix>.<Suite>.<ENV>.Tests, where Suite is Schema or DataQuality;
    the prefix comes from the contract's dataProduct, then its name (override with --suite-prefix)
  severity: warning (or info) rules go to separate <ENV>WARN suites: reported, but they never fail `run`
  Test names are "ODCS <contractId> <ruleId>: <description>"; ruleId is the ODCS `id`, else a path like orders.customer_id.quality[0]
  Generated files start with "// Generated by pql-odcs" and name their contract id; generate refuses to overwrite a hand-written file
    or another contract's suite (same prefix) unless --force; give contracts that share a dataProduct distinct --suite-prefix values
  --pql-assert 0.7|0.8 picks the PQL.Assert version generated for (default 0.7; `run` defaults to auto: it asks the model
    with PQL.Assert.LibraryVersion() and falls back to 0.7); 0.8 needs a model with PQL.Assert 0.8.0 or later
  approximated = generated, but DAX semantics differ (named in the reason): primaryKey/unique/duplicateValues are skewed by blanks;
    required on string columns also counts empty strings as nulls
  Both workflows are supported: regenerate in CI (`contract run`, generated files git-ignored), or commit the generated
    suites and fail CI on drift (`generate` then `git diff --exit-code`); see the pql-odcs README
  run --output adds a "contract" key (per-rule trace) to the run-tests JSON; run --log-format emits one annotation per failed rule
  Model names come only from the contract: customProperties pbiTable (schema object) / pbiColumn (property), else the ODCS logical name;
    there is no sidecar mapping file
  Never claim a rule is enforced when coverage reports it skipped; quote the reason instead
}
```

## What v0.1 maps

| ODCS rule | Generated check |
|---|---|
| Schema object present | `Tbl.ShouldExist` |
| Properties present | `Tbl.ShouldHaveColumns` (one per table) |
| `--closed-schema` | `Tbl.ShouldNotHaveExtraColumns` |
| `required: true`, `nullValues mustBe 0` | `Col.NullRateShouldBeAtMost(…, 0)` (approximated on string columns) |
| `primaryKey`, `unique`, `duplicateValues mustBe 0` | `Col.ShouldBeDistinct` (one shared check per column; approximated, because blanks skew it) |
| `rowCount` (all comparators except `mustNotBeBetween`) | `Tbl.ShouldHaveRows` / `ShouldHaveRowCount` / `ShouldHaveMoreRowsThan` / comparisons on `COUNTROWS` |

Everything else is reported as **skipped**, with the release that will map it:
- `type: sql`, `custom`, and `text` rules;
- composite keys, nested properties, and ODCS 3.2 `map` / `vector` properties;
- column types, `logicalTypeOptions`, relationships, and ODCS 3.2 `enum`;
- `missingValues` and `invalidValues`;
- non-zero thresholds;
- SLA properties.

With `--pql-assert 0.8` (needs PQL.Assert 0.8.0 or later in the model), more rules map exactly:
- `required: true` and `nullValues` use `Col.NullCountShouldBeAtMost`, which counts true nulls only; empty strings are not nulls;
- `nullValues` with an absolute ceiling, or `unit: percent` (`Col.NullRateShouldBeAtMostV2`);
- `primaryKey` uses `Col.ShouldBePrimaryKey`; `unique` and `duplicateValues mustBe 0` use `Col.NonBlankValuesShouldBeDistinct`;
- composite `primaryKey` and schema-level `duplicateValues` over two or more properties use `Tbl.RowsShouldBeDistinct`;
- `duplicateValues` with a ceiling uses `Col.DuplicateCountShouldBeAtMost`, and `rowCount mustNotBeBetween` uses `ShouldNotBeBetween`;
- simple patterns (`^literal`, `literal$`, a bare literal) use `Col.ValuesShouldStartWith` / `EndsWith` / `Contains` (starts/ends are approximated: DAX text comparison ignores case);
- a `latency` SLA with a `table.column` element uses `Col.MaxDateShouldBeWithinDays` (approximated: it is the age of the newest value, and depends on when the test runs).

Options shared by `generate`, `coverage`, and `run`:
- `--env ENV` — environment token for suite names, e.g. `DEV` (generate/run; required).
- `--suite-prefix NAME` — override the suite name prefix.
- `--closed-schema` — also fail when a table has columns the contract does not list.
- `--pql-assert 0.7|0.8` — PQL.Assert version to generate for (`run` also accepts `auto`, its default).
- `--fail-on-skipped` — exit 1 when any rule is skipped (generate/coverage; strict CI).
- `--dry-run` — print the DAX instead of writing files (generate).
- `--force` — overwrite suite files that pql-odcs did not generate (generate/run).

`run` also accepts `--verbose`, `--output FILE`, and `--log-format azuredevops|github`, plus the connection options of `run-tests`: `--tenant-id`, `--workspace-id`, `--dataset-id`, `--client-id`, `--client-secret`.

Usage:
```
# See which contract rules can be enforced before generating anything
pql-test contract coverage orders.odcs.yaml

# Check the contract and that every table/column exists in the model
pql-test contract lint orders.odcs.yaml --model ./MyModel

# Write the suites into the PBIP model's DAXQueries/ folder
pql-test contract generate orders.odcs.yaml ./MyModel --env DEV

# Generate, run, and trace in one step (model open in Power BI Desktop)
pql-test contract run orders.odcs.yaml ./MyModel --env DEV

# CI: GitHub annotations, JSON results, and fail if any rule cannot be enforced
pql-test contract coverage orders.odcs.yaml --fail-on-skipped
pql-test contract run orders.odcs.yaml ./MyModel --env DEV --output results.json --log-format github

# Trace an earlier run-tests result file back to contract rule ids
pql-test run-tests ./MyModel --env DEV --output results.json
pql-test contract trace orders.odcs.yaml results.json
```
